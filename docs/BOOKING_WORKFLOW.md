# Booking workflow

Customers choose a Garage motorcycle or a year-specific trim for guest booking, then select services, package components, and parts attached to that workshop work. The booking form requests live candidate start times using variable service and component durations, workshop hours and breaks, bay capacity, mechanic schedules, daily capacity, leave, special closures, and required specializations. Services in the same labor group can declare shared operation minutes (such as opening a CVT cover); those minutes are included once in both the labor estimate and scheduled duration. Manual mode presents a dated slot map with available, limited, full, break, closed, and held states; automatic mode recommends the earliest suitable arrival. A selected time is a request, not a hold. The server recomputes duration and checks the slot again at submission; the admin checks capacity under database locks before confirming it. Member accounts may select the configured deposit percentage; guests are required to pay the full approved amount before confirmation.

An admin reviews the request, sets the approved total and duration, assigns mechanics, and chooses a schedule. If a selected part has unverified fitment, approval requires a documented motorcycle fitment review. Scheduling checks operating days/hours, breaks, mechanic leave, required specializations (or a reasoned override), daily capacity, time overlap, and configured service-bay capacity in a transaction. Unpaid appointments are held temporarily until the configured deadline.

The payment deadline is checked by `minex:expire-unpaid-bookings`. Expiration cancels the temporary appointment, releases held stock, preserves status history, and creates a refund request for any verified partial payment. Payment does not confirm automatically: an admin must review submitted payment proof. Once the required deposit is verified, the booking and appointment become confirmed and the work order opens.

Admins can set automatic or manual booking-status control globally and override it per booking. Automatic lifecycle changes are tied to submission, payment, and workshop events; appointment start time alone never marks physical work as started. Every manual override records its actor, time, and reason. Customers can submit cancellation or reschedule requests for admin review; an accepted reschedule is rechecked against mechanic and bay capacity. Mechanics record check-in, inspection, recommendations, work items, and handover on the assigned work order. Customers can follow booking status and assigned appointments, review private inspection evidence, decide on each recommendation, and see payment/refund history. See [payment](PAYMENT_WORKFLOW.md), [mechanic](MECHANIC_WORKFLOW.md), and [vehicle catalog](VEHICLE_CATALOG.md) guides for operational detail.
